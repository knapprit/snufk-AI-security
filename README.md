# SNUFK

Это гибридная система класса XDR (Extended Detection and Response), предназначенная для высокоточной детекции угроз и автоматического предотвращения вторжений. Система устраняет разрыв между обнаружением атаки и реакцией на неё, автоматизируя рутинную работу аналитиков SOC L1.

## Цель проекта

Сократить время пребывания злоумышленника в сети (Dwell Time) до минимума. В отличие от стандартных SIEM-систем, Sentinel Hybrid XDR не просто пассивно собирает логи, а активно коррелирует события сетевого и системного уровней, принимая решение об изоляции угрозы за секунды.

## Ключевые возможности
- **Гибридный анализ:**
  Система связывает воедино сетевые процессы и процессы операционной системы
  Сетевой уровень: Глубокий анализ пакетов (DPI) через Suricata и Zeek.
  Системный уровень: Мониторинг процессов, реестра и USB-событий через Microsoft Sysmon.

  Если веб-сервер получает подозрительный запрос (Network), а затем порождает аномальный дочерний процесс (Host), система идентифицирует это как подтвержденный взлома
  
- **Риск-ориентированный подход:**
  Алгоритм выявляет атаку на этапе разведки. Каждое подозрительное действие (сканирование портов, поиск скрытых директорий, манипуляции с куки) добавляет баллы в аккумулятор риска. Блокировка происходит ДО того, как хакер выполнит основной этап атаки. Так же это минимизирует False Positives.
- **Автоматическое реагирование:** Мгновенная блокировка IP через Windows Firewall при достижении порога риска и отправляет готовый отчёт об инциденте.
  
- **Интеллектуальная отчетность:**
Система автоматически генерирует профессиональные отчеты об инцидентах, экономя до 90% времени аналитика.
Отчет включает:
Detailed Timeline - Хронология всех "звоночков" атаки.
Root Cause Analysis - Определение вектора проникновения.
Recommended Actions - Конкретные шаги по устранению последствий.

- **Оптимизация под SMB:** Работает на системах с 8 ГБ ОЗУ благодаря Kafka KRaft и Python.

## Архитектура
Общая схема архитектуры

Архитектура разделена на 4 логических уровня:
1. **Уровень сенсоров
Здесь происходит первичный сбор данных.

    Suricata (Docker). Сетевой глаз. Она ищет в сетевых пакетах конкретные сигнатуры атак.

   Zeek (Docker). Работает как самописец, записывает кто, куда зашел, какой файл скачал, сколько байт передал. Это создает контекст.

    Microsoft Sysmon (установленный в саму ОС Windows). Следит за процессами внутри ОС. Он знает, к примеру, если "Блокнот" вдруг начал выходить в интернет или если веб-сервер запустил командную строку.

2. **Уровень конвейера данных.

На этом этапе данные упаковываются и передаются в центр обработки.

Vector (установленный на Windows ОС). Сборщик-унификатор. Он работает прямо в системе, собирает JSON-логи от Сурикаты, текстовые логи от Зика и системные события Windows, объединяя их в один поток.

Kafka KRaft (Docker): Интеллектуальная шина данных. Это "склад-буфер". Если атак станет слишком много, Kafka удержит все логи в очереди, не давая системе упасть или потерять улики.

3. **Уровень аналитического ядра.

    Normalizer (в main.py). Переводит потоковые данные в общий JSON чтобы main мог корректно обработать данные.

    Correlation Engine (Движок связей). Самая важная часть. Он связывает сетевой алерт от Сурикаты с конкретным процессом из Sysmon.

    Risk Scoring (Аккумулятор риска). Система суммирует баллы за каждое подозрительное действие. 40 баллов за сканирование портов, 60 за поиск скрытых папок. Когда сумма = 100, принимается решение о защите и блокировке iP злоумышленника.

4. **Уровень реагирования.

Действие системы в ответ на угрозу.

IPS Module. Прямое управление Windows Firewall. Система сама прописывает правила блокировки IP.

Reporting (Rich CLI): Моментальная отрисовка отчета. Пока аналитик только открывает глаза, система уже нарисовала ему таблицу с хронологией атаки.

## Установка

###Полное руководство по установке и запуску
Система является гибридной: Аналитический центр работает в Docker, а Агенты слежения и блокировки работают напрямую в Windows.

**Шаг 0: Подготовка (Prerequisites)
Перед началом убедитесь, что у вас установлены:

    Docker Desktop (с включенным WSL2).

    Python 3.9 или выше.

    Git.
**Шаг 1: Клонирование и структура
Откройте терминал (PowerShell) и выполните:

    git clone https://github.com/knapprit/snufk-AI-security.git
    cd snufk-AI-security

Важно: Убедитесь, что у вас есть две основные папки: snufk (инфраструктура) и core (пульт управления).

**Шаг 2: Запуск инфраструктуры (Docker)
Эти компоненты отвечают за сбор сетевого трафика и хранение логов.

1.Перейдите в папку snufk:
cd snufk

2.Запустите контейнеры (Kafka, Suricata, Zeek):
docker-compose up -d --build

3.Проверка: Введите docker ps. Вы должны увидеть 4 работающих контейнера.
Примечание: Если контейнер kafka-kraft упал, подождите 10 секунд и введите команду запуска еще раз.

**Шаг 3: Настройка Sysmon
Чтобы система видела процессы и USB, нужно установить системный монитор от Microsoft.

1. Скачайте Sysmon с официального сайта Microsoft Sysinternals.
2. Распакуйте его в удобную папку.
3. В этой же папке должен лежать ваш файл конфигурации sysmonconfig-export.xml.
4. Откройте PowerShell от имени Администратора и установите Sysmon:
.\Sysmon64.exe -i sysmonconfig-export.xml

**Шаг 4: Настройка Vector
Vector будет перекачивать логи из файлов и журналов Windows в Docker.

1. Скачайте Vector для Windows (версия 0.55+) с официального сайта.
2. Распакуйте архив.
3. В папке windows-agent проекта найдите файл vector.yaml. Отредактируйте его, указав правильные пути к папке вашего проекта (например, C:/Users/.../snufk-AI-security/snufk/suricata/logs/eve.json) и запустите Vector через PowerShell (от Администратора):
   #Укажите путь к вашему vector.exe
.\vector-0.55.0-x86_64-pc-windows-msvc\bin\vector.exe --config .\snufk\vector.yaml

Если всё верно, вы увидите надпись "Vector has started" и поток логов.

**Шаг 5: Запуск "Мозга" и IPS (Python)
Это финальный этап. Запуск системы принятия решений.

1. Откройте новое окно PowerShell (от Администратора).
2. Перейдите в папку core:
   cd core
3. Установите необходимые библиотеки:
   pip install -r requirements.txt
4. Запустите систему:
   python main.py

**Шаг 6: Тестирование

Запустите уязвимое приложение (оно должно быть в вашем Docker-стеке или запущено отдельно).

С другого устройства (или из WSL2) попробуйте провести атаку.
Разведка: Просканируйте порты через nmap. В окне main.py вы увидите желтые предупреждения.
Взлом: Попробуйте зайти в браузере на http://[IP]:8080/WebGoat/.git/config.

Результат: main.py мгновенно выдаст отчет о предотвращении инцидента, а атакующий IP будет заблокирован в Windows Firewall.

##Устранение неполадок

Блокировка не срабатывает: Убедитесь, что main.py запущен от имени Администратора. Без этого Python не может управлять Брандмауэром.
И обязательно свяжитесь с автором проекта

# Будущее проекта

## Вектор развития и масштабирование

Проект SNUFK находится в активной фазе разработки. Моя цель — превратить систему в полноценное Enterprise-решение для автоматизации ИБ. 

### Ближайшие планы по усилению системы:
- **Интеллектуальное расширение базы (Threat Intelligence)** 
  Постоянное пополнение `signatures_db.py` новыми паттернами на основе актуальных данных о CVE и тактик MITRE ATT&CK. Я работаю над автоматическим импортом индикаторов компрометации (IOC) из открытых источников.
- ** Поведенческий анализ (Behavioral Analysis)** 
  Переход от простых баллов риска к анализу аномалий. Система будет обучаться "нормальному" поведению пользователя, чтобы мгновенно распознавать даже неизвестные ранее угрозы (0-day).
- ** Оптимизация производительности:** 
  Внедрение Redis для хранения памяти инцидентов, что позволит системе обрабатывать трафик крупных корпоративных сетей без задержек.
- ** Модули оповещения и оркестрации (SOAR):** 
  Добавление мгновенных уведомлений в Telegram/Slack и интеграция с облачными API для изоляции целых сегментов сети.
